# 提出前の再計算と自己点検 v1

既存の科学的結果を変更せず、検証手順と保存値の整合を調べる。新しい有利な指標や除外を選ぶための実験ではない。失敗した場合はログを保持し、原因と修正を追記する。

1. 標準ライブラリによる入力・参照時刻と署名の再点検。全国・地点・NZ・非正規化SARS。
2. 保存済みの全国2倍上昇の元の通知件数と拡張実装の一致、全ROCのAUCを別の既存実装で照合。探索的な比率・方法・地域も区別する。
3. 保存された国別共有学習の全週モデルの学習行と成熟締切、分位点再生を点検。各国の最初の1発行週を同じ特徴から再学習して照合する。独立再現ではない。
4. `config/reproduction.json`の単一入口を、提出予定コミットの新しい複製で通し実行する。出力先はそのソース複製の外。研究ディレクトリ内の`.verify-work/`を使うがGit管理から除外し、容量上限には含める。ローカルGitオブジェクトを共有する複製の場合も明記する。
5. 保存予測から全主要解析・補足解析を再計算し、表の全セルを比較する。相対許容差1e-9、絶対1e-11。入力・特徴・小さなモデルの再学習照合は各コードのより厳しい条件を使う。図と本文は再計算表から生成する。

各実験ジョブは最大30分、通し実行の内側は29分で停止する。標準版がこの上限を超える場合は失敗を残し、地点の追加区間補正だけを省く`--quick`版を用いる。どの表を省いたかを明示し、元の保存結果との関係を書く。新しいAI API、モデルの再ダウンロード、外部送信は不要。

複製前に総容量と、Git管理された作業ファイル・再計算出力の見込みを確認する。必要なら研究用ディレクトリ内の再取得可能なパッケージキャッシュだけを専用パッケージ管理コマンドで消去し、研究データ・未加工結果・履歴は保持する。上限に接近したら開始しない。

自己点検では、本文で引用箇所を確認した資料、近い研究の追加検索、定量下限という用語、固定された主要解析と探索的追加、入力履歴とモデル学習時点、同一入力と近い入力・定数・補完、欠測による分母、臨床効果を測っていない範囲を点検する。未解消の点は隠さない。初稿のAI査読は人間による別エージェントの実行を待つ。
