# 通し実行の再試行 v2

v1の初回通し実行E141は42計算段階を終了したが、最終の厳密なCSV照合で失敗した。入力品質の2表だけが、データセットを処理する順（全国・NZ・地点 / 全国・地点・NZ）の違いで行順不一致となった。全64表をデータセット名で安定整列して診断すると全行全列が元の許容差で一致した。診断は通し実行の成功とは扱わず、E141の失敗を残す。

修正は再計算設定を生成する際の入力品質データセットの順を、元のE097と同じ固定順にすることだけである。数値解析・元の期待表・比較の許容差・厳密な行順照合は変えない。題名下の公表時刻の代理という説明、プレプリントの表示と著者表示、表の集計水準の日本語表記も整理する。指標・仮説・除外・数値は変えない。

E141の全出力、実行記録、各段階stdout/stderrと不一致の2表を保存する。容量内で新しい出力先に全43段階を再実行するため、初回出力と元の完了済み実験成果物がSHA-256で完全一致する場合に限り、検証用の重複ファイルを元成果物へのハードリンクに置換する。置換前後の全バイトの一致を確認し、対応表と容量を保存する。最初の計算が完了した後の保管上の重複除去であり、計算の代わりに結果を複製する処理ではない。異なるファイルと失敗ログはそのまま残す。元の実験成果物は以後変更しない。新しい再計算出力にはリンクを事前に置かず、空の別ディレクトリから計算する。

再試行前に元の検証ソースのハッシュ不変を確認し、修正コミットへ作業用複製を更新して新たな入力ハッシュ一覧を作る。ローカルGitオブジェクトと既存の依存環境は引き続き共有する。同じ研究者の自己再実行で、独立再現とは呼ばない。

再試行も内側29分、外側30分、同時実験上限2を守る。初回の実測出力容量を踏まえて容量の余裕を確認し、上限に収まらなければ開始しない。成功条件は全43段階の終了、64表の厳密な照合、主張の照合、検証ソースに科学的入力の変更がないこと。新しいAPI・推論・ネットワーク取得は行わない。
