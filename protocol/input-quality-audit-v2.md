# 入力品質監査 v2：公開版ごとの実測・補完来歴

E096の後の点検で、数値・日付が同じ入力IDでも、ある値が前方補完か実測かの来歴が公開版によって異なることを確認した。IDは数値入力の重複除去を目的とし、実測状態を符号化していない。保存された代表入力のメタデータとケースのメタデータの不一致は、地点の全入力可ケース36,732件中72件、全国・NZは0件だった（`review/input-quality-metadata-consistency.json`）。

E096は補完割合を入力IDの代表メタデータから読み取っており、補完に関する層分けが不正確だった。旧出力は保持し、最終論文の補完に関する主張には用いない。ケースに保存された各公開版の`context_length`と`imputed_context`を使って割合と実測数を計算し直す。日付・数値の同一性、全対象のスコア、モデル予測自体には影響しない。

閾値・比較・対象・再抽出条件はv1から変更しない。新しい実験IDで再計算し、全対象と入力同一性の件数・損失比がE096と一致すること、変わった補完層の件数を点検する。E038のユニーク数値履歴の監査にある補完メタデータも代表状態に過ぎないため、論文ではケース単位の来歴と混同せず、ユニーク履歴の定数列と末尾反復の点検に用いる。
